# 댐퍼 계산기 수정 및 검증

이 문서는 2026-09-09의 초기 로컬 검증 기록이다. 이후 배포 승인 및 추가 요구사항을 반영한 최신 상수 감사·구현·검증 내용은 [최신 검증 문서](../docs/damper-calculator-validation.md)를 참조한다. 현재는 전후 스프링 분리·다이나모 모드·2/3/4-way를 지원하며 초기 구조는 미확인으로 클릭 계산을 보류한다.

검증일: 2026-09-09. 기존 빌드 도구가 없는 정적 HTML/CSS/JavaScript 프로젝트다. 기존 작업 트리는 깨끗한 상태였으며 push, 배포, Firebase 데이터 쓰기는 수행하지 않았다.

## 변경 범위

- `js/damper.js`: 검증·물리 계산·클릭 전수 검사·결과 문자열을 순수 함수로 분리. UI 오류 처리, 읽기 전용 현가질량, 클립보드 실패 처리 추가.
- `index.html`: 댐퍼 탭 내부만 변경. 질량·MR·샤프트 속도·단위 정의, 클릭 기준 선택, 선택적 롤 목표, 고급 감쇠비 목표, 조절기별 공통 클릭 결과 추가.
- `css/style.css`: 댐퍼 전용 반응형 그리드, 오류 표시 및 표 내부 스크롤 추가.
- `tests/damper.test.cjs`: Node 기본 테스트 러너를 사용하는 회귀 테스트 40개.
- `tests/serve.cjs`: 추가 패키지 없이 실행하는 localhost 전용 정적 서버.

다른 탭의 HTML은 HEAD와 비교해 동일함을 확인했다. `js/storage.js`, `js/app.js`와 나머지 탭 스크립트는 변경하지 않았다. 댐퍼 계산기는 원래처럼 저장 스키마와 분리되어 있으며, 탭 전환 시 입력은 유지되고 새로고침 시 초기값으로 돌아간다.

## 계산 및 동작

- `m_sf = (M × p − m_uf) / 2`, `m_sr = (M × (1−p) − m_ur) / 2`, `M_s = M − m_uf − m_ur`. 입력 M은 운전자·주행 유체 포함 전체 질량, p는 전체 차량 정적 전륜 축중 비율, 언스프렁 질량은 축 전체다.
- `K_wheel = K_spring × MR²`, `f = √(K_wheel × 1000 / m_corner) / (2π)`, `C_crit = 2√(K_wheel × 1000 × m_corner) / 1000` 유지. MR은 댐퍼 이동량/휠 이동량이다.
- 축 롤 강성은 좌우 두 바퀴를 포함하는 `2 × K_wheel × (track/2)²`, 단위는 N·mm/rad다.
- 컴프레션·리바운드 각각 클릭 0~N을 검사하고 저속·고속 목표 범위의 교집합만 표시한다. Full Hard 기준을 기본값으로 하며 Full Soft 기준 전환 시 동일 물리 설정의 클릭 표기가 반전된다. 보편 권장값·자동 합격·스프링 배분에 따른 댐퍼 조정 지시는 제거했다.
- 모든 필수 입력은 숫자·유한성·물리적 조건을 JavaScript에서 검사한다. 오류는 입력 바로 아래 표시하고 결과 전체를 `—`로 지우며 복사 버튼을 비활성화한다. 극단값의 연산 오버플로도 차단한다.
- 브라우저 정지를 막기 위한 명시적 전수 검사 한도는 조절기당 총 10000클릭이다. 이는 물리 권장값이 아니다.

## 재현 명령과 결과

저장소 루트에서 실행한다.

```powershell
node --test tests/damper.test.cjs
Get-ChildItem js/*.js | ForEach-Object { node --check $_.FullName }
git diff --check
node tests/serve.cjs
```

브라우저 주소: `http://127.0.0.1:8765/`.

자동 테스트 40/40 통과. 모든 앱 JavaScript 문법 검사와 diff 공백 검사 통과. 테스트는 기본값, 질량 변경 및 보존식, 클릭 양 끝점·기준 반전·목표 교집합·고정 힘·정확한 목표 경계, 입력 오류, 큰 값·작은 값, 단위 변환, 복사 결과 및 저장 회귀를 포함한다.

실제 로컬 브라우저에서 확인한 항목:

- 총중량 300→600 kg: 전체 현가질량 542.670 kg, 전륜 134.1105 kg, 후륜 137.2245 kg, 전륜 주파수 1.605974 Hz로 변경. 다른 탭을 왕복해도 입력 유지.
- 저속 속도 0, 전륜 배분 100%, 스프링 −1, 저속 압축 Full Hard 90 < Full Soft 95, 총중량 빈 값, 총 클릭 1.5: 각각 오류 표시·결과 비활성화·복사 비활성화. NaN/Infinity 출력 없음. 빈 입력은 전체 선택 후 Backspace로 재현했다.
- 52.5→70 N/mm: 299.78→399.71 lbf/in 실시간 반영.
- 고급 설정에서 컴프레션 저속·고속 목표를 각각 0~1로 설정: 전·후륜 Full Hard 11~12클릭, Full Soft 0~1클릭으로 전환. 초기값 복원도 확인.
- 롤 목표 50~60%: 후륜 편향/오버스티어 방향. 목표 20~30%: 전륜 편향/언더스티어 방향. 기본값에서는 자동 판정 없음.
- 결과 복사 버튼으로 실제 클립보드 텍스트를 읽어 단위, 질량, 클릭 기준, 공통 클릭 범위와 설정 없음 네 항목을 확인.
- 1440×1000 데스크톱: 입력·결과 2열, 가로 넘침 없음. 390×844 모바일: 1열, 댐퍼 요소의 오른쪽 경계가 viewport를 넘지 않음. 페이지 scrollWidth 약 385px ≤ 390px. 표만 내부 너비 520px / 컨테이너 약 323px로 스크롤되며 키보드 가로 이동을 확인. 표의 터치 종료는 앱의 탭 전환 제스처로 전파하지 않도록 처리.
- 다른 9개 탭 전환 및 화면 렌더링 확인. 브라우저 콘솔 error/warn 0건.
- 실제 Firebase 동기화 수신 및 저장 상태 표시 확인. 운영 데이터 쓰기는 하지 않음. 기존 `save`, JSON 내보내기 및 불러오기는 모의 Firebase/파일 환경에서 왕복 테스트했으며 스키마 유지와 댐퍼 계산의 공유 상태 비변경을 확인. 현재 코드에는 localStorage/sessionStorage 기반 저장 경로가 없으며 파일 기반 JSON 저장을 사용한다.

## 모델 가정과 근거

좌우 대칭, 일정 MR, 전·후 공통 스프링 레이트 및 다이나모 힘, 클릭별 힘의 끝점 선형 보간을 가정한다. ARB·타이어 강성을 포함하지 않는 단순 현가 모델이다. F/V는 해당 샤프트 속도의 secant 등가값이며 가스압·마찰력이 포함되면 오차가 생길 수 있다. 초기 목표값은 기존 값을 유지한 사용자 설정 출발점이며 차량별 권장값을 새로 만들지 않았다.

전륜 롤 모멘트 배분 증가에 따른 일반적 언더스티어 방향은 [Wang 등, 2005 논문](https://skoge.folk.ntnu.no/prost/proceedings/cdc-ecc05/pdffiles/papers/0739.pdf)의 서론과 일치한다. 타이어, 캠버 변화, 롤센터, 트랙 차이 등으로 실제 밸런스는 달라질 수 있다.

사용자가 제시한 [Penske 8300 매뉴얼](https://www.penskeshocks.com/hubfs/Resources/Manuals/8300-DA-SHOCK-Manual.pdf?hsLang=en)과 [Öhlins SU184 매뉴얼](https://ohlins.com/storage/1D16F5E09DF4BA3A826417A93BD928C68CE61E91501C36839951A4AC6F71E183/33f9fce44b364c4f92be22cca98356ee/pdf/media/4acac9f94d1e4e87b09333bf6c32db17/MI_SU184.pdf)을 확인했다. 실제 댐퍼의 클릭 기준과 총 클릭 수는 해당 제품 매뉴얼 및 다이나모 측정값에 맞춰 입력해야 한다.
