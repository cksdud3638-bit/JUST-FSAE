# 팀 공용 비밀번호 로그인 적용

## 구현
- Firebase Email/Password 인증으로 비밀번호를 확인한다. 공개 코드에는 비밀번호/해시/관리자 키를 넣지 않는다.
- js/auth-config.js에는 공용 계정 이메일(공개 로그인 식별자)만 설정한다. 운영 공용 계정 이메일을 설정했다.
- 로그인하지 않으면 앱을 숨기고 데이터 동기화를 시작하지 않는다. 승인된 members/{uid}=true 확인 후 앱을 초기화한다.
- SESSION 지속성을 사용한다. 로그아웃 시 구독을 해제하고 데이터 연결을 끊고 새로고침하여 이전 화면/입력 상태를 정리한다.
- database.rules.json은 루트 읽기/쓰기를 거부하며, 비밀번호 인증을 한 승인된 UID만 /just에 접근하도록 제한한다. /members는 본인 항목만 읽을 수 있고 클라이언트 쓰기는 금지한다.
- 기존 라디에이터의 로그인 전 자동 읽기를 로그인 이후로 이동했다. 불러온 값을 자동으로 서버에 재저장하지 않는다.

## 운영 적용 절차
1. just-fsae 프로젝트에서 Authentication 시작, Email/Password 활성화.
2. 사용자가 공용 계정 이메일과 새 공용 비밀번호를 Firebase 사용자 추가 화면에 직접 입력한다. 이 비밀번호는 Google 관리자 계정 비밀번호와 다르게 설정한다.
3. 생성된 공용 계정 UID를 확인하고 Realtime Database의 /members/{uid}에 boolean true를 관리자 권한으로 추가한다. /just 기존 데이터는 유지한다.
4. 현재 데이터베이스 규칙을 확인/백업한 뒤 database.rules.json을 적용한다. 익명 REST 읽기가 Permission denied인지 확인한다. 공개 회원가입으로 만든 다른 계정에도 접근을 허용하지 않는다.
5. auth-config.js의 teamEmail에 공용 계정 이메일을 설정한다. 최종 테스트 후 main push 및 Pages 배포.
6. 실제 사이트에서 사용자가 공용 비밀번호로 로그인해 데이터 조회/저장/로그아웃을 확인한다. 인증 전 읽기/쓰기는 거부되어야 한다.

## 검증
자동 테스트 104개 통과. 추가 7개: 비로그인 데이터 미조회, 승인된 회원만 초기화, 권한 회수 시 구독 해제/잠금, 로그아웃 메모리 정리, 지연된 인증 결과의 재개방 방지, 비밀번호 실패/중복 제출, 규칙의 익명/미승인 계정 차단 조건.
규칙 테스트는 로컬 표현식 검증이며 Firebase 서버 적용 검증을 대신하지 않는다. 로컬 화면에서 로그인 전 앱 비노출, 틀린 비밀번호 거부를 확인했다.

## 서버 적용 확인
사용자가 공용 계정을 직접 생성하고 규칙 게시를 명시적으로 승인했다. Firebase 콘솔에서 database.rules.json과 동일한 규칙을 게시했고 /members 아래에 공용 계정 UID의 boolean true 허용 항목을 추가했다. 기존 /just 데이터는 변경하지 않았다.

비로그인 GET /just.json?shallow=true 요청이 HTTP 401 / Permission denied로 차단됨을 확인했다. 로그인 화면과 로그아웃은 로컬 모의 인증으로 검증했다. 실제 공용 비밀번호는 사용자만 입력하므로 운영 계정 로그인 확인은 사용자 입력 이후 수행한다.

이전 공개 규칙은 docs/database-rules-before-auth.json에 감사 목적으로 보관했다. 이 파일을 운영 규칙으로 다시 적용하면 안 된다.
