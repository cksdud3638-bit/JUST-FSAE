# 부품·예산 관리 통합 및 검증

## 화면과 계산 기준

- `6 부품·예산 관리`로 예산/부품 탭을 통합. 댐퍼 7, 라디에이터 8. 기존 `budget`, `parts`, `weight` 탭 호출은 통합 탭으로 연결한다.
- 전체 예산·배정·미배정·예상·실제·잔액·등록 건수·무게 요약 → 파트별 현황 → 검색/필터/정렬과 부품 목록 → 접힌 기타 지출 → 기존 차량 무게 배분/코너 무게 순서.
- 예상 비용 = 계획 수량 × 예상 단가. 실제 지출 = 구매 수량 × 실제 단가 + 기타 지출. 총무게 = 계획 수량 × 개당 무게(g).
- 가격 미입력은 `null`, 무상은 `0`. 미입력 가격은 합계에서 제외하고 안내한다. 기존 보유는 무게/등록 건수에 포함, 제외 상태는 기본 목록과 요약에서 제외한다.
- 파트 삭제 시 지정한 다른 파트로 부품·기타 지출·배정 예산을 함께 이동한다. 미분류는 삭제하지 않는다. 배정 초과는 경고하되 저장을 허용한다.
- 데스크톱 표는 내부 스크롤과 고정 헤더, 600px 이하에서는 상세 펼치기가 있는 부품 카드로 전환한다.
- 범위별 JSON 보고서, PDF 보고서, 요약 복사. 전체 백업은 상단 저장 버튼의 JSON을 사용한다.

## 저장 및 이전 데이터

기존 저장소는 브라우저 localStorage 대신 Firebase `just/budget`와 `just/parts`를 사용했다. `cost`는 개당 비용이며 기존 표에서 `cost * qty`로 합산했다. 기존 예산 지출과 부품 비용 간 자동 연결 키는 없었다.

새 기준 데이터는 `just/partsBudget`, `version: 1`이다. 최초 접속 시 루트 트랜잭션에서 최신 원본으로 변환하고 저장한다. 다른 기기와 충돌하면 서버의 최신 값으로 재시도한다. 이미 version 1이면 재변환하거나 항목을 추가하지 않는다. 이후 편집도 트랜잭션으로 처리하여 서로 다른 항목의 동시 편집을 보존한다. 동일 항목의 동시 편집은 마지막 저장이 반영된다. 실패는 완료로 표시하지 않는다.

- 기존 `parts`/`budget` 경로를 지우거나 덮어쓰지 않으며 `partsBudget.legacyBackup`에도 최초 원본을 보존한다.
- 기존 파트 이름/예산 배정을 먼저 유지하고 기본 파트를 보충한다. 파트가 없는 부품은 미분류로 옮긴다.
- 기존 부품의 `cost`는 예상 단가로 옮기고 구매 수량은 0, 실제 단가는 미입력으로 둔다. 이전 지출은 기타 지출에 보존한다. 이름이나 금액이 같다는 이유로 연결하지 않는다.
- 명시적인 `partId`가 있는 확장 데이터만 해당 부품 실제 지출로 이동한다. 연결 원본도 보존한다. 구매 수량 0인 항목은 기타 지출로 남긴다.
- 오래된 장부의 금액을 부품 실제 단가에도 다시 입력할 때는 같은 구매에 해당하는 기타 지출을 먼저 정리해야 한다. 화면에 안내한다.
- `S.parts`는 통합 데이터의 호환용 읽기 뷰로 제공하여 연료·무게 배분·대시보드가 같은 무게를 사용한다. 기존 코너 무게 등 별도 저장 경로는 유지한다.
- 전체 JSON 백업은 version 2.0으로 통합 데이터와 원본 호환 데이터를 포함한다. 예전 1.1 백업에 예산이 빠져 있으면 현재 통합 예산과 기타 지출을 유지한다. 가져오기는 사전 검증 후 한 번의 Firebase update로 반영한다.
- 구버전 화면은 보존된 원본 경로를 읽으므로, 통합 후에는 새 버전 페이지에서 편집해야 한다.

## 검증 기록 (2026-09-12)

자동 검사: `node --test tests/damper.test.cjs tests/parts-budget.test.cjs` (61개).
전체 JS 구문 검사 및 `git diff --check` 수행.

검사 범위: 기존 데이터 이전/원본 보존/재변환 방지, 미분류, 파트 추가·수정·삭제와 예산 이동, 예상·실제·무게 수식, 보유/제외, 누락/0원 구분, 전체/파트 합계, 초과 예산, 검색·필터·정렬, 비정상 숫자, Firebase 빈 배열 처리, 트랜잭션 재시도와 실패, 구/신 JSON 복원, 댐퍼 회귀 검사.

브라우저 검증은 로컬 `/test.html`에서 수행했다. 이 경로는 `tests/serve.cjs`만 제공하며 Firebase SDK를 로컬 모의 저장소로 교체한다. 운영 Firebase에 테스트 부품/예산을 입력하지 않았다.

- 기존 샘플: 부품 2건, 기타 지출 3,000원, 무게 2.15kg, 잔액 997,000원 확인.
- 부품 추가: 계획 3 × 10,000원 = 30,000원, 구매 2 × 18,000원 = 36,000원, 무게 3 × 500g = 1.5kg 확인.
- 부품 수정/파트 이동/무상 보유/제외/삭제, 기타 지출 7,000원 추가 확인.
- 파트 이름 변경/위·아래 순서/삭제 후 부품·지출 이동, 배정 300,000원 초과 경고 확인.
- 별도 두 화면에서 변경 반영 및 새로고침 유지 확인. 실제 Firebase 통신은 운영 배포 후 별도 확인한다.
- 모바일 390px: 문서 가로폭 385px, 카드 약 365px로 전체 가로 넘침 없음. 규격 검색과 카드 편집 확인.
- 데스크톱 1440px: 문서 가로폭 1434px, 넓은 표는 내부 스크롤에 한정. PDF 내보내기 완료 및 요약 복사 완료 안내 확인.
- 모든 기존 탭을 순회하여 정상 활성화 확인. 수정된 테스트 서버의 새 브라우저 화면에서 오류/경고 0건.

운영 서버 사전 읽기 검사: 기존 부품 0건, 기존 예산 지출 0건, 통합 장부는 아직 없음. 기존 데이터가 있는 경우의 마이그레이션은 위 샘플과 자동 검사로 검증했다.
