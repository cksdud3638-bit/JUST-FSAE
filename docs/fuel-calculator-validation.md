# 연료 전략 계산기 검증

## 발견한 문제와 수정

1. `parseFloat(value) || default`로 여유율 0%와 보충량 0L가 기본값으로 바뀌었다. 빈값/음수/무한대/잘못된 숫자는 오류로 처리하며 0은 허용된 항목에서 유지한다. 입력 오류 시 이전 결과와 그래프를 지운다.
2. 탱크 비율을 미리 100%로 잘라 초과 경고가 작동하지 않았다. 표시 비율은 실제 비율을 사용하고 막대 길이만 100%로 제한한다.
3. 거리로 계산한 필요량과 올림한 랩 수로 계산한 그래프가 서로 달랐다. 입력 거리를 기준으로 하며 마지막 구간은 부분 랩으로 계산한다.
4. 기존 그래프는 잔량 0.5L 미만에서 자동 보충했지만 계획은 다른 시점을 사용했다. 보충 계획과 그래프가 하나의 계산 결과를 공유한다. 보충 시 기존 잔량을 유지하고 탱크 빈 공간과 잔여 필요량을 넘지 않게 주입한다.
5. 기존 계획은 20회 이후 잘라내거나 부족한 연료로 같은 랩에 반복 정차할 수 있었다. 최대 10,000랩의 유한한 구간 계산으로 교체하고 다음 구간을 감당하지 못하면 이유와 함께 중단한다. 완주하지 못한 경로를 완주한 것으로 표시하지 않는다.
6. 총 준비 연료를 한 번에 실은 것으로 중량에 더했다. 출발 탑재량에 입력한 밀도를 곱해 중량을 계산한다. 등록 부품 합계가 실제 완성차 총중량으로 오해되지 않도록 이름과 포함 범위를 명시했다.

## 계산 기준

- 기본 소모량[L] = 입력 거리[km] / 연비[km/L].
- 안전 여유분[L] = 기본 소모량 × 여유율 / 100.
- 총 준비 연료[L] = 기본 소모량 + 안전 여유분.
- 출발 탑재량[L] = min(총 준비 연료, 사용 가능한 탱크 용량).
- 출발 연료 중량[kg] = 출발 탑재량 × 연료 밀도[kg/L].
- 서킷 1랩 기본 소모량 = 서킷 길이 / 연비. 마지막 부분 랩은 실제 남은 거리만큼 소모한다.
- 각 구간 종료 시 안전 여유분을 남기는 보수적 계획이다. 보충 허용 시 다음 구간의 소모량과 여유분을 확보할 필요가 있을 때 랩 완료 지점에서 한 번 보충한다. 보충량은 입력한 최대 주입량, 탱크 빈 공간, 남은 준비 연료 중 최솟값이다. 단 한 번의 보충으로 다음 구간을 감당할 수 없으면 해당 설정은 불가능으로 표시한다. 최소 정차 횟수 최적화는 하지 않는다.
- 기본은 보충 비허용이다. 사용자가 보충 시뮬레이션을 켤 수 있으나 이는 해당 대회의 보충 허용을 의미하지 않는다.

기존 연비 8.5km/L, 서킷 1.2km, 거리 22km, 용량 5.5L, 여유율 10%, 보충량 5L 및 밀도 0.74kg/L는 검증된 실차/대회 상수가 아닌 계산 예시로 명시했다. 밀도는 수정 가능하다. 일정 연비와 일정 밀도 가정으로 랩별 부하/온도/회수 불가능한 연료량은 자동 추정하지 않는다. 탱크 입력은 실제 사용 가능한 용량을 입력해야 한다.

기본 예시: 기본 소모량 2.588235L, 여유분 0.258824L, 총 준비량 2.847059L, 주행 18.333333랩 상당, 종료 잔량 0.258824L, 출발 연료 중량 2.106824kg.

## 상태 및 검증

계산 입력은 이 화면의 일시적인 값으로 유지하며 공유 데이터에 저장하지 않는다. 새로고침 시 초기값으로 돌아가는 기존 동작을 명시했다. 부품 중량은 통합 장부의 계획 수량 기준 투영을 읽고 제외 부품을 빼며 원본을 변경하지 않는다.

`node --test tests/*.test.cjs`: 총 80개 통과(연료 전용 9개 포함). 기본 산식, 0 입력, 부분/정수 랩, 탱크 초과, 보충 부족, 잔량 보존, 여러 조건 조합의 연료 수지, 비정상 입력 및 과도한 랩 수, 중량 연결, 이전 결과 제거, 공유 상태 불변을 확인했다.

로컬 테스트 페이지에서 기본 결과, 여유율 0%, 탱크 1L, 보충 0/0.7L, 빈 연비와 복구를 직접 조작해 확인했다. 모바일 390px 결과 배치와 가로 넘침 없음, 콘솔 오류 없음을 확인했다. 운영 데이터에 테스트 값을 저장하지 않았다.
